## Как поддерживать документацию

- Описывайте **фактические** вызовы API и ответы, а не предположения.
- Непроверенные места помечайте ⚠️ и заводите открытый вопрос.
- Принятые архитектурные решения фиксируйте отдельными ADR в
  `decisions/NNNN-краткое-название.md`.
- При изменении контракта API или состава сервисов обновляйте README и эту
  страницу.
